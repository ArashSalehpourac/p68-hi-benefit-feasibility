# P68 — P1 queue simulator: PRELIMINARY results (2026-10-02)

Status: PRELIMINARY. Payloads = 120-image partial snapshot of P0 (full 600-image CSV not yet used). Network = my own
log-normal AR(1) uplink + log-normal RTT/server time (assumptions, not measurements; traces unused, licence unresolved).
Script: p1_queue_sim.py (new post-freeze; implements frozen gate definitions). Grid: uplink median 1/2/5/10/20 Mbit/s x
load 0.3/0.6/0.85 x D in {50,...,1200} ms, N=60,000 requests/config, 50% clean + 50% corrupted mix, JPEG q75. Seed 0.
Reproduce: python p1_queue_sim.py --csv payload_p0.csv --n 60000 (grid CSV not uploaded; regenerated by the script).

## What the numbers say (JPEG, sigma_logR = 0.6)
- G3 (frozen: Var_S/(Var_S+Var_R) of transfer time): 0.39-0.44 everywhere -> does NOT fire (threshold 0.10). It falls to ~0.20
  with a very variable link (sigma 0.9) and rises to ~0.75 with a stable link (sigma 0.3); never below 0.10. Caveat: this definition
  ignores RTT, server time and queue wait, and is invariant to absolute uplink rate, so it flatters the payload.
- G1 proxy (is q informative, and does payload move it?): the feasibility penalty on severe-noise inputs
  (mean q clean - mean q noise sev 4-5) reaches 0.12-0.50 (low load) but only inside a narrow D window:
  best D ~200 ms at 1 Mbit/s, ~150 ms at 2, ~100 ms at 5-20. On my 9-point D grid it holds (in-window share >=0.2 AND penalty >=0.05)
  for at most 2 contiguous D values (typically 1) -> the "effect at >=3 contiguous D values" requirement is NOT met by this proxy.
  Higher load widens queue wait and shrinks the window; at 20 Mbit/s and load 0.85 it is absent. This is the knife-edge predicted earlier.
- G4 (q-hat calibration, 2-fold cross-fit logistic): stratum-weighted ECE 0.014-0.026 (<0.05, passes). Worst single stratum
  reaches 0.078 in some configs, but strata have only ~150-450 requests, where 10-bin ECE has a sampling floor of roughly 0.03-0.05, so
  that is probably noise; to be re-checked at N>=200k and with the full payload pool.

## Not tested / limits
No benefit G, no accuracy, no oracle-vs-q-hat policy comparison (G10), no queue-state conditioning check (G5). The D grid here is coarse
(ratio ~1.3-1.5); the frozen 5-value grid must be placed around the window found here. Everything depends on simulator assumptions.
Known simulator approximations: latent rate at transmit start is propagated independently per request; EMA features use the previous
request's measurement regardless of whether its transfer has finished; min stratum size for ECE is 150.

## Decision implication (my reading, not frozen)
P1 does not kill the idea, but G1 is the binding constraint: the paper only works in a deadline window about one grid step wide, and it
shifts with uplink rate and load. Next: (1) rerun on full 600-image payloads, N>=200k; (2) finer D grid around the window;
(3) replace assumed network parameters by fits to the licensed/permitted traces or published summary statistics.
